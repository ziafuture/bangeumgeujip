# 방금그집

운전 중 "방금 그거 뭐야?" 한마디로 몇 초 전에 지나친 가게를 찾아 찜하는 Pleos Connect 앱입니다.

## 동작

1. FusedLocation 위치를 최근 2분만 메모리에 둡니다. 속도는 위치 변화로 계산합니다.
2. 주행 중(최근 3분 안에 2 m/s 이상 이동)에만 마이크 소리를 음성 구간으로 자릅니다. 녹음 파일은 만들지 않습니다.
3. Pleos 온디바이스 STT 결과에 "방금", "아까", "저장", "찜" 같은 호출어가 없으면 바로 버립니다.
4. 말을 시작한 시각 기준 10초 전~1초 후의 경로 주변 장소를 검색해 점수를 매깁니다. 경로와의 거리, 통과 후 1~4초 반응, 왼쪽·오른쪽, 업종, 이름 일부를 봅니다.
5. 말한 업종("고기집", "카페"…)과 방향("우측")에 맞는 후보가 있으면 맞지 않는 후보는 뺍니다.
6. TTS로 확인합니다(최대 3번).
   - 1등이 분명하면: "오른쪽에 있던 ○○ 맞아요?" → "응", "아니", "그 옆", "아니 그 앞에 거", "방금 지난 거", 다른 가게 이름 일부.
   - 1·2등이 비슷하면 지나친 순서대로 이름을 대며 묻습니다: "꽃살집과 우둔살집 중 어디예요?" (화면에는 "아까 본 가게 / 방금 본 가게" 카드)
     - "꽃살집이었던 거 같은데"처럼 이름 일부로 답하면 그 가게만 → "꽃살집 찜했어요." 두 이름에 같이 들어간 말("살집")은 구분에 쓰지 않습니다.
     - "모르겠어", "몰라", "기억 안 나", "헷갈려" → "그럼 꽃살집, 우둔살집 둘 다 찜했어요." ("둘 다"도 같음, 이름까지 말함)
     - "아까 거", "방금 거"로 순서로 답해도 됩니다. 대답이 없으면 후보로 묶어 두고 차 세운 뒤 고릅니다.
     - 묻지 않고 바로 묶어 두려면 `new Dialog(out, false)`.
   - 유명 체인점(스타벅스, 공차, GS25, 맥도날드 등 약 50곳, `Chains.java`)은 순위를 낮춥니다. 운전자가 한눈에 알아보는 곳이라 "방금 그거 뭐야"의 대상이 아닌 경우가 대부분이기 때문입니다. 브랜드 이름을 말했거나("방금 스타벅스") 편의점·햄버거·마트·약국·주유소를 물으면 낮추지 않고, 체인점이 확실히 더 가까운 시점에 지나갔다면 그대로 1등이 됩니다.
   - 찜할 때는 항상 가게 이름으로 말합니다: "연남갈비 찜했어요." (예전: "연남동 갈비집, 찜했어요.")
   - 대답이 없으면 후보 최대 3곳을 묶어 저장하고, 주차 후 목록에서 "이거였어요"로 고릅니다.
7. 확인되면 한 문장으로 알려 줍니다: "저장했어요. 동교동에 있는 고기집이에요." 이미 찜했던 곳이면 "3주 전에도 찜했던 곳이에요."를 덧붙입니다. 카카오 로컬 API에 없는 영업시간·평점·리뷰는 말하지 않고, 정차 후 목록의 "영업시간·리뷰"(카카오맵 링크)와 "전화"로 넘깁니다.
8. **질문 타이밍(안전):** 방향지시등이 켜져 있거나(Vehicle SDK), 150m 안에 회전이 있거나, 200m 안에 어린이보호구역·철길·사고다발 등 주의 구간이 있으면(NaviHelper) 질문을 미루고 안전해지면 묻습니다. 30초 안에 기회가 없으면 묻지 않고 후보째로 저장합니다.
   - **마이크 양보:** 전화 통화나 시스템 음성비서(Gleo)가 마이크를 쓰면 Android가 이 앱의 녹음을 무음으로 바꿉니다. `AudioRecordingCallback`으로 그 상태를 받아 듣기를 멈추고 화면에 "통화·음성비서 중이라 잠시 쉬어요"를 띄웁니다. 끝나면 자동으로 다시 듣습니다.
9. **반응 시간 개인화:** "응"으로 확인한 찜마다 "지나친 뒤 몇 초 만에 말했는지"를 기록하고, 3건 이상이면 그 중앙값(0.8~5초)을 순위 기준으로 씁니다. 기본값은 2.5초입니다. 숫자만 저장합니다.
11. **목적지 근처 찜한 곳:** 내비 경로가 시작되면(`onRouteStarted` → `getDestinationInfo`) 목적지에서 걸어서 10분 안(700m)의 찜한 곳을 찾아 "목적지 근처에 3주 전 찜한 꽃살집이 있어요. 들를까요?"라고 한 번 묻습니다. "응"이면 지금 경로에 경유지로 넣습니다. 목적지당 한 번만 묻고, 찜한 곳 자체로 안내를 시작한 경우에는 묻지 않습니다. 에뮬레이터의 실제 Pleos 내비로 경로 시작 → 제안 → 경유지 추가까지 확인했습니다.
12. **동승자 인식:** 차량 SDK의 조수석 착석 센서(`CAR_SEATS`, 일반 권한)로 동승자가 있는지 압니다. 동승자가 있으면:
    - 두 곳 질문에 처음 한 번 "옆에서 화면으로 골라 주셔도 돼요."를 붙이고, 화면에 "조수석에서 눌러 골라도 돼요"와 "둘 다 찜하기" 버튼, 한 곳 질문·들를까요 질문에는 누르는 버튼을 띄웁니다.
    - 대답을 8초 기다립니다(혼자일 때 5초). 둘이 상의하고 대답하는 경우가 많아서입니다.
    - "그거 뭐야"처럼 "방금"이 없는 말은 서로에게 하는 말로 보고 "방금 지나친 가게요?"를 묻지 않습니다.
    - 센서가 없는 차에서는 혼자 운전할 때처럼 동작합니다.
    - 디버그: `--ez passenger true|false`, `--es dest "위도,경도,이름"`(제안만), `--es route "위도,경도,이름"`(실제 내비 경로 요청).
13. **주고받는 대화 (`Chat`):** 찜하기 말고도 옆자리 사람처럼 받아 줍니다. 모두 앱이 가진 찜 기록만 씁니다.
    - "아까 찜한 데 어디였지?", "이번 주에 찜한 고깃집 뭐 있었지?" → "이번 주 찜한 고기집은 꽃살집, 홍대최대포, 두 곳이에요. 어디로 갈까요?" → "첫 번째" / "꽃살집" → 길 안내(주행 중이면 경유지). 한 곳이면 "가 볼까요?" → "응" / "가자". 오늘·어제·이번 주·지난주와 가게 종류를 알아듣고, 화면에도 목록 버튼을 띄웁니다.
    - "찜한 꽃살집으로 가자"는 바로 안내합니다.
    - 혼자 운전 중 "와 저기 맛있겠다", "줄 엄청 길다" → "방금 그 가게, 찜해 둘까요?" (동승자가 있으면 끼어들지 않음)
    - 앱이 말한 뒤 15초 안의 "고마워" → "천만에요." 그 밖의 "고마워"는 동승자에게 한 말로 봅니다.
    - 같은 종류를 일주일에 세 번째 찜하면 "요즘 고기집 자주 찜하시네요."를 한 번 덧붙입니다.
14. **간판 색 (`SignColors`):** "좀전에 빨간 간판 음식점 뭐야?" → "빨간 간판이면 스시엔준과 생활맥주 중 어디예요?" → "두 번째 거" → "생활맥주 찜했어요. 빨간 간판으로 기억해 둘게요." 한 곳을 확정했을 때만 그 가게에 색을 기록하고("모르겠어"로 둘 다 담으면 기록 안 함), 다음에 "빨간 간판"이라고 하면 그 가게를 올리고(+0.8) 다른 색으로 기록된 곳은 내립니다(−0.5): "왼쪽 빨간 간판 생활맥주 맞죠?" 지도 API에는 간판 색이 없고 거리뷰 캡처·AI 분석은 제공사 정책상 허용되지 않아(카카오 데브톡 답변 기준) 운전자의 말만 씁니다. 지금은 기기 안에만 저장하며, 운전자끼리 나누려면 서버가 필요합니다.
10. **도착 브리핑:** 목적지에 도착하면 "이번 주행에서 2곳을 찜했어요. 근처에 지난번 찜한 ○○도 있어요."
11. 확인된 찜 400m 안에 다시 들어오면 "들를까요?"를 묻고, "응"이면 NaviHelper로 경유지를 추가합니다. 목적지 도착 시 이번 주행에서 찜한 수를 알립니다.

## 빌드

저장소 루트에서:

```sh
./gradlew :passed:testDebugUnitTest :passed:assembleDebug
```

APK: `passed/build/outputs/apk/debug/passed-debug.apk`

### 장소 데이터

- 키가 없으면 `src/main/assets/demo_places.json`의 **가상 장소**(이름 앞에 `[데모]`)를 씁니다.
- 카카오 로컬 API를 쓰려면 루트 `local.properties`에 `kakao.restKey=발급받은_REST_API_키`를 넣고 다시 빌드합니다. 키는 커밋하지 않습니다.

## 에뮬레이터 시연

1. Pleos Connect 에뮬레이터를 cold boot하고 마이크 입력을 켭니다.
2. `adb install -r passed/build/outputs/apk/debug/passed-debug.apk`
3. 앱에서 **켜기** → 마이크·위치 권한 허용.
4. 에뮬레이터 Extended controls → Location → Routes에서 `passed/demo/demo-route.gpx`를 불러와 재생합니다(동쪽 직진 43 km/h, 약 96초).
5. 가게를 지난 1~3초 뒤 "방금 그 카페 뭐야?"라고 말합니다. 마이크가 어렵다면 **입력한 문장 보내기**로 같은 경로를 탈 수 있습니다.
6. 위치가 움직이지 않는 환경에서는 **정차 중에도 듣기(시연용)**를 켭니다.

## 확인 상태 (2026-11-02)

- 단위 테스트 30개 통과: 안전 타이밍, 반응 시간 학습, 브리핑 문장, 도착 요약, 역추적 순위, 좌/우, 업종 필터, 갈비 골목, 이름, 도로 밖 제외, 대화 흐름(한 곳/두 곳/순서/이름/둘 다/묶음 저장/최대 3번), 카카오 응답 파싱, 데모 경로 5개 시나리오.
- `lintDebug` 오류 0 (경고: 아이콘, targetSdk, 백업 규칙).
- **Pleos 에뮬레이터(roadmoment_pleos_21, API 34) 실행 확인**
  - 포그라운드 서비스(마이크+위치) 시작, FusedLocation 위치 수신, 위치 변화로 주행 판정.
  - 에뮬레이터에서 카카오 로컬 API 호출 성공(인터넷 정상). 연남동 좌표에서 실제 카페 후보 선정.
  - 온디바이스 STT 연결과 PCM 전달 확인. TTS 재생(Pleos 음성 서비스 AudioTrack)과 완료 콜백 확인.
  - "방금 그 카페 뭐야" → "왼쪽에 있던 연베이크샵, 카페 맞아요?" → "응 맞아" → 저장. 대답이 9초 안에 없으면 미확인으로 저장.
  - 찜한 곳 → 안내 중이 아니면 NaviHelper `requestRoute`로 길 안내 시작 확인. 안내 중일 때 `addWaypoint`로 경유지 추가 확인(2026-11-03).
  - 시연용 문장 주입(디버그 빌드 전용): `adb shell "am start -n io.roadmoment.passed/.MainActivity --es inject '방금 그 카페 뭐야'"`
- 확인된 SDK 주의점
  - TTS는 `initialize()` 성공 뒤에만 `addEventListener` 가능(반대 순서면 `lateinit property tts` 예외).
  - 에뮬레이터 내비 엔진 위치(판교 근처)는 `adb emu geo fix` 위치와 따로 움직임.
  - Google Play 서비스 없음 → Firebase App Check(Play Integrity) 등 GMS 의존 기능은 사용 불가.
- **실제 음성 테스트** (Mac `say -v Yuna` → Mac 마이크 → 에뮬레이터 `-allow-host-audio`)
  - "방금 그 카페 뭐야?" → STT "방금 그 카페에 뭐야?" → 카카오 카페 15곳 중 경로 근처 12곳 순위 → "…스타벅스 홍대역점… 맞아요?" → "응, 맞아" → 저장.
  - 근접 알림 동작: 찜한 곳 근처를 다시 지나가자 "지난번에 찜한 ○○ 근처예요. 들를까요?"
  - 수정한 문제: 대답 창이 첫 0.8초 무음에 닫힘, 무음 조각을 받은 STT가 15초 멈추고 이후 인식이 꺼짐 → 무음은 보내지 않고, 지연 시 STT 자동 재연결(8초).
  - 디버그 빌드는 튜닝용으로 인식 문장을 `BangeumHeard` 태그로 logcat에 남깁니다. 릴리스 빌드는 남기지 않습니다.
- **업종·순서 고르기** (카카오 실제 데이터, 홍대 고기집 구간을 북쪽으로 주행)
  - "방금 우측 고기집 뭐야" → 고기집·오른쪽으로 인식, 23곳 → 21곳 → "꽃살집 맞아요?" → "아니 그 앞에 거" → "홍대최대포 맞아요?"(먼저 지난 곳) → "응" → 저장.
  - 대답이 늦으면 후보 3곳 묶음 저장 → 목록에서 "이거였어요"로 확정 확인.
  - 둘 중 하나 묻기는 단위 테스트(갈비 골목 시나리오)로 확인. 실제 데이터에서는 아직 그 조건이 나오지 않음.
  - 발견: `pleos.car.permission.FUSED_LOCATION`은 위험(런타임) 권한 → 앱에서 요청하도록 수정. 권한 창에 설명이 없어 "알 수 없는 작업"으로 표시됨 → 요청 전 안내 화면 필요.
  - 수정: 근접 알림("들를까요?") 대기 중에 들어온 새 요청이 대답으로 처리되던 문제, 미확인 장소에 근접 알림이 걸리던 문제.
- **브리핑·안전·개인화** (에뮬레이터): "방금 우측 고기집 뭐야" → "꽃살집 맞아요?" → "응" → "저장했어요. 동교동에 있는 고기집이에요." 목록에 주소·전화·영업시간·리뷰 링크 표시. 반응 시간 표시(확인 1건, 3건부터 적용).
  - 방향지시등은 에뮬레이터가 user 빌드라 adb로 바꿀 수 없어 단위 테스트로만 확인. 회전·주의 구간은 경로 안내 중에만 와서 미확인. 도착 브리핑도 미확인(문장은 단위 테스트).
- **전체 기능 점검 (2026-11-03, emulator-5580)**
  - 권한 안내 → 시스템 권한 4개 → 서비스 자동 시작 확인.

### 찜 목록 정리 (2026-11-03)
- 문제: 운전 중 두 곳을 같이 담은 후보 카드("어디였나요?")와 확정한 곳이 한 줄로 섞여, 시험 데이터 68건 중 61건이 후보 카드로 목록을 덮음.
- 수정: 후보는 위 "골라 주세요 N"에 2건만 보이고 "나머지 N건 보기"·"후보 모두 지우기"로 접음. 확정한 곳은 "찜한 곳 N" 아래 최근순 / 업종별 / 지역별(구 단위) 탭으로 묶고, 고른 탭은 기억함. 탭을 바꿔도 스크롤 위치 유지.
- 업종은 카카오 카테고리 전체 경로 + 가게 이름으로 정함(`Hints.kindOf`). 이제 저장 시 전체 경로를 남기고 화면에는 마지막 단계만 보여 줌. 예전 데이터(마지막 단계만 저장)는 이름으로 보완, 못 정하면 "기타".

### 부르는 이름 (2026-11-03 추가 → 2026-11-04 제거)
- 이름으로 시작한 말만 처리하는 선택 기능이었으나 뺐음. Pleos SDK에 키워드 감지가 없어 이름을 정해도 어차피 계속 받아쓰고, "이름 없이 바로 묻는다"는 핵심 장점과 충돌함. 동승자 대화 오인식은 조수석 착석 센서(동승자 모드)로 줄임.

### 대답·업종 말 넓히기 (2026-11-03)
- "아니" 대답: 아니라고·아닌데·아님·노우·노·No·nope·놉·싫어·안 돼·필요 없어·틀렸어도 NO. "노래"처럼 '노'로 시작하는 다른 말은 제외. 순서 말("아니 나중 거")과 취소("아니 됐어")가 여전히 우선.
- "좀 전에", "조금 전에"도 "방금"처럼 요청으로 받음.
- 목록에 없는 업종: "호떡집", "감자탕 가게"처럼 '○○집/가게'로 말하면 ○○을 카카오 키워드로 찾고 "감자탕집 맞죠?"로 물음.
- 목소리로 이름 등록 시 이름과 많이 다른 철자("봄"에 "고마워")는 저장하지 않음.
